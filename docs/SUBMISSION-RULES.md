# 统一提交规则（2.0）

## 练习、组号与代表

练习一至四分别使用 lesson-01 至 lesson-04；组别统一为 group-01、group-02 等。老师维护根目录 course.json，可继续新增组别，每组指定一名 GitHub 提交代表。null 是待登记，不是任意账号都可提交。

每组每个练习共用一份作品，由代表上传。其他成员可共同制作，再交给代表统一提交。临时换代表请先请老师更新登记并处理该组未关闭的 PR。

## 作品位置

```text
submissions/
  lesson-01/
    group-01/
      README.md
      ...作品文件
    group-03/
      README.md
      ...作品文件
  lesson-02/
    group-01/
      ...
```

学生本机文件夹名称不影响远端归档。可以说完整路径、当前项目内目录，或环境已提供路径的「选中的文件夹」。Skill 上传源目录内的内容，不会额外套上本机文件夹名称。

## 提交和重交

```text
使用 aibt-workshop，提交练习一第三组，作品在当前选中的文件夹。
```

缺练习、组号或可定位目录时只补充缺少信息。Skill 检查实际登录账号与老师 main 的登记，创建/确认自己的 Fork，再创建分组分支和 PR。

- 分支：aibt/<login>/lesson-01/group-03。
- 标题：[练习01][第03组] <login>。
- 同组同练习只有一个打开的 PR，修改后更新同一单；合并/关闭后补交使用 -r2 等新分支。
- 每个作品根部必须有 README.md，写练习、组号、作品用途、入口及参考来源，可参考 [范本](../templates/submission/README.md)。
- 只新增/更新文件，不自动删除远端旧文件。重新命名后旧版保留；确需清理请明确列出路径，由老师审阅维护 PR。
- 每组每个练习最多 200 个文件、单个 20 MiB、总计 50 MiB，保留图片/PDF/演示文稿等原始格式。

正式作业 PR 等待老师审阅；合并后出现在课程 main。连接测试 PR 使用独立目录并保留草稿，无需合并，也不计入作业总览。

## 老师检查与总览

自动检查登记代表、课次、组号、分支、标题、实际文件范围、README、重命名来源、符号链接和文件限制。跨组/跨练习、旧版账号路径或自行修改名单的作业会被拒绝。

[课堂作品总览](https://github.com/f3484134/AIBT-WORKSHOP-261107/actions/workflows/submission-overview.yml)的最新成功运行 Summary 会列出全部练习与组别。待审不代表检查已通过，请同时查看 PR Checks。

维护课程内容的 PR 由老师添加 course-maintenance 标签，再人工审阅全部差异。学生不能借此改变提交范围；标签权限属于仓库维护者。
