# 统一提交规则（2.0）

## 同时支持个人和小组作品

每个练习、组别可以同时接收多名成员的个人作品和一份小组共同作品。练习一至四对应 lesson-01 至 lesson-04；组别统一为 group-01 等。老师在根目录 course.json 为每组分别登记：

- members：可以交个人作品的 GitHub 账号列表。
- representatives：可以代表本组交共同作品的 GitHub 账号列表。

同一账号可以属于多个组，也可以代表多个组；必须分别在相应组的列表中登记。代表不必同时是该组个人提交成员。空列表表示尚未开放对应角色，不能自行加入；连接测试仍可执行。

## 统一目录

```text
submissions/
  lesson-01/
    group-03/
      individual/
        member-a/
          README.md
          ...个人作品
        member-b/
          README.md
          ...个人作品
      team/
        README.md
        ...小组共同作品
  lesson-02/
    ...
```

个人作品独立保存，不能修改其他成员的目录。小组共同作品由登记代表维护，和个人作品分开。老师仍按练习、组别查看，两类提交分别统计，不把一份小组作品当成全组个人作品均已完成。

本机文件夹名不影响远端目录。可以提供完整路径、当前项目内目录，或环境已提供路径的「选中的文件夹」。上传源目录内部内容，不额外套上本机文件夹名。

## 自然语言提交

```text
使用 aibt-workshop，提交练习一第三组的个人作品，作品在当前选中的文件夹。
使用 aibt-workshop，代表第三组提交练习一的小组作品，作品在当前选中的文件夹。
```

缺练习、组号、提交类型或可定位目录时，只补充缺少信息。Skill 核对实际登录账号和老师 main 登记，不根据文件夹名或名单猜测提交类型。

| 项目 | 个人作品 | 小组共同作品 |
|---|---|---|
| CLI 类型 | individual | team |
| 授权列表 | members | representatives |
| 目录 | lesson-NN/group-NN/individual/<login>/ | lesson-NN/group-NN/team/ |
| 分支 | aibt/<login>/lesson-NN/group-NN/individual | aibt/<login>/lesson-NN/group-NN/team |
| PR 标题 | [练习NN][第NN组][个人] <login> | [练习NN][第NN组][小组] <login> |
| 待审 PR | 每人每练习每组一单，可多人并行 | 每组每练习一单，不同代表不能重复开单 |

同一作品修改时更新打开的 PR；已关闭/已合并后使用 -r2 等版本。更换小组代表前处理原有共同作品的未关闭 PR。课程维护标签的 PR 不计入作业，也不复用为正式作业。

每份个人作品或小组共同作品最多 200 文件、单个 20 MiB、总计 50 MiB，根部须有 README.md，说明类型、练习、组别、用途、入口及来源。只新增/更新本次文件，远端旧文件不自动删除；清理须明确指定路径，由老师审阅维护 PR。

## 检查和总览

自动检查身份、角色、课次、组号、类型、分支、标题、实际范围、README、重命名来源、链接和大小。禁止跨组、跨练习、跨个人目录及个人/小组类型串用，名单只能由老师维护。

[课堂作品总览](https://github.com/f3484134/AIBT-WORKSHOP-261107/actions/workflows/submission-overview.yml)的最新成功运行 Summary 按练习、组号、类型和账号排序，显示待登记、未交、草稿、待审和已合并，并提供作品及 PR 链接。待审不代表检查通过。

连接测试使用独立目录并保留草稿，不计入作业。维护课程的 PR 由老师添加 course-maintenance 标签，再人工审阅全部差异。
