# 统一提交规则（2.1）

## 学生自报组别，无需预建名单

每组既可多人分别提交个人作品，也可由代表提交一份共同作品，两类可以同时存在。练习一至四对应 lesson-01 至 lesson-04；学生填写自己的课堂组号（1–99），工具整理成 group-01 等。首次出现的新组别也可提交，无需老师维护 members、representatives 或预建文件夹。

账号来自 GitHub 实际登录结果，不允许冒用他人账号。一个账号可跨组、跨类型提交；小组作品表示学生声明自己代表该组。老师审核 PR 时确认真实组别和代表身份，自动检查不验证组内关系。[course.json](../course.json) 只定义开放练习和自报模式，不能用 Fork 中的配置代替老师 main。

## 统一目录

```text
submissions/
  lesson-01/
    group-03/
      individual/
        member-a/
          README.md
          ...个人作品
        member-b/
          README.md
          ...个人作品
      team/
        README.md
        ...小组共同作品
  lesson-02/
    ...
```

个人作品独立保存，不能修改其他账号目录。小组共同作品单独保存，不把一份共同作品算成全组个人作品都已完成。本机文件夹名不影响远端目录；上传源目录内部内容，不额外套上本机文件夹名。

## 自然语言提交

```text
使用 aibt-workshop，提交练习一第三组的个人作品，作品在当前选中的文件夹。
使用 aibt-workshop，代表第三组提交练习一的小组作品，作品在当前选中的文件夹。
```

也可提供当前项目内可定位的文件夹名或完整路径，不必自己创建 GitHub 目录。缺练习、组号、提交类型或可定位目录时，只补充缺少信息，不猜组号和类型。

| 项目 | 个人作品 | 小组共同作品 |
|---|---|---|
| CLI 类型 | individual | team |
| 身份 | 实际登录账号 | 实际登录账号，声明代表本组 |
| 目录 | lesson-NN/group-NN/individual/<login>/ | lesson-NN/group-NN/team/ |
| 分支 | aibt/<login>/lesson-NN/group-NN/individual | aibt/<login>/lesson-NN/group-NN/team |
| PR 标题 | [练习NN][第NN组][个人] <login> | [练习NN][第NN组][小组] <login> |
| 待审 PR | 每人每练习每组一单，可多人并行 | 每组每练习一单，不同代表不能重复开单 |

修改复用打开的 PR；已关闭/已合并后用 -r2 等版本。换代表前处理原有共同作品的未关闭 PR。多人同时创建时保留编号较早单，只关闭本次新建的较晚重复单，保留上传分支并返回链接；无法确认时提示协调，暂不报告成功。

每份作品最多 200 文件、单个 20 MiB、总计 50 MiB，根部须有 README.md，说明练习、组号、类型、用途、入口及来源。只新增/更新本次文件，远端旧文件不自动删除；清理须明确指定路径，由老师审阅维护 PR。

## 检查和总览

自动检查作者、来源、开放练习、组号格式、类型、分支、标题、范围、README、重命名来源、链接和大小，禁止修改本次目标以外的组别、练习、类型或他人个人目录。

[课堂作品总览](https://github.com/f3484134/AIBT-WORKSHOP-261107/actions/workflows/submission-overview.yml)自动汇集已出现的组别和提交者，按练习、组号、类型和账号排序，显示暂无提交、草稿、待审和已合并及相关链接。待审不代表检查通过。没有完整名单，无法判断全班谁还没交；“暂无提交”不代表任何人的缺交结论。

连接测试使用独立目录并保留草稿，不计入作业。维护 PR 由老师添加 course-maintenance 标签后人工审阅，不计入作业或重复检查，也不复用为正式提交。
