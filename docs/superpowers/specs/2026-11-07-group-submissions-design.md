# 按练习与组别归档课堂作品

## 已确认的目标

老师希望学生作品按练习顺序、组别统一归纳，由学生测试账号提交维护 PR，再由老师另一账号审阅和合并。课程有 4 个练习，组数尚未确定，预计至少约 5 组；各组代表账号未知。所有新增和改写的课程内容使用简体中文，兼容 Qoder 与 WorkBuddy。

## 提交契约

- 远端作品目录：`submissions/lesson-NN/group-NN/`，两个编号均为 01–99。
- 每组一位提交代表。课程根目录 `course.json` 是课次和组别登记的唯一来源；helper 从老师仓库 main 读取，检查器从 PR 的可信 base commit 读取。
- 先配置练习 01–04、组别 01–05。代表使用 null 占位；没有登记时拒绝正式提交，不自动把测试账号加入名单。老师可增删组别。
- 代表账号可对应多个组，但一次提交必须明确一个练习和一个组别。
- 分支：`aibt/<login>/lesson-NN/group-NN`，关闭或合并后递增 `-r2`。同一组同一练习只能有一个打开的正式 PR。
- 标题：`[练习NN][第NN组] <login>`。提交必须包含根目录 README.md，说明作品及入口。
- 更新保留远端旧文件，不自动删除，不强推，不合并；验证文件 SHA 以及 PR base、head、状态与范围。
- 连接测试继续使用 `connection-tests/<login>/` 和原来的草稿 PR，不需要正式分组登记。

## 检查与归纳

- 检查真实 PR 作者、fork owner、固定分支、登记代表、课次、组号、变更路径、重命名来源、README、文件类型及数量/大小。拒绝跨组变更、删除、符号链接和重复打开的组别 PR。
- 课程维护 PR 由老师添加 `course-maintenance` 标签后走人工审阅，不作为学生作品。
- 使用 pull_request_target 的检查和总览工作流只检出可信 base 代码，不执行学生代码，不自动合并或推送 main。权限只读。
- 总览根据可信 main 的登记、已合并目录和分页读取的 PR 生成，按练习、组号排序；展示待登记、未交、草稿、待审和已合并，并提供链接。待审不代表已通过检查。
- 总览发布到 Actions 运行摘要，并可本地生成 Markdown；通过 README 提供入口。无需配置网站或机器人写入 main。

## 分发与升级

- 保留 Node.js 20+，不引入 npm 运行依赖，不要求学生本地 Git 仓库。
- Qoder 继续安装到项目 `.qoder/skills/aibt-workshop`；WorkBuddy 继续导入含 `aibt-workshop/` 的 ZIP，保留 scripts 与 references。
- Skill 明确版本为 2.0.0。重新生成 ZIP 和 SHA-256，提供可重复打包脚本，验证安装器拒绝覆盖。
- 已有个人目录不自动迁移；旧版 Skill 正式提交会被新版检查拒绝，需统一升级。旧连接测试 PR 保留。
- 当前项目已安装的旧 Skill 保持原样，待 PR 审阅后再更新。

## 验收

自动测试覆盖组号/课次/登记、未授权与跨组拒绝、二进制、重试复用、关闭后新分支、并发与错误哈希、分页总览、PR 检查、Qoder 安装与 ZIP 完整性。保留原始连接测试能力。独立检查 Skill 对已知组号、缺组号和未登记代表的行为。真实 Qoder/WorkBuddy UI 加载需在各产品完成，不能以本地脚本测试替代。
