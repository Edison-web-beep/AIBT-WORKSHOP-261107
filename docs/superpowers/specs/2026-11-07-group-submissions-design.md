# 课堂作品归档设计

## 目标与约束

课程有 4 个练习，组数和账号不预先确定。学生自行填写课堂组号，不让老师维护各组 members/representatives。支持同组多人个人提交、代表交共同作品、同一账号跨组或跨类型提交。简体中文，Qoder 项目安装和 WorkBuddy ZIP 共用 Skill。由 yuhsiuli 更新维护 PR #3，老师另一账号审核；不自动批准、合并或改 main。

## 最终提交契约

- 个人目录：submissions/lesson-NN/group-NN/individual/<login>/；共同目录：submissions/lesson-NN/group-NN/team/。
- course.json version=3、submissionMode=self-reported，只列出开放练习01–04，不含组别或账号名单。拒绝不兼容旧配置，不能静默回到名单模式。
- 学生明确提供练习、1–99 的组号、individual/team 和作品目录；不猜组号或类型，只问缺少信息。首次出现的新组别也可提交，目录由工具生成。
- login 来自实际登录。代表身份为学生声明，真实组别关系由老师在 PR 中确认；自动检查不声称验证组内权限。
- 分支 aibt/<login>/lesson-NN/group-NN/<kind>，关闭/合并后 -r2 等；标题 [练习NN][第NN组][个人/小组] <login>。
- 个人每账号每组每练习一单，共同作品每组每练习一单。个人及共同作品互不阻挡；创建前后复查并发，只关闭本次新建的较晚重复 PR，保留较早链接和上传分支。远端查询不是原子锁，重复或关闭未确认不报告成功，不关闭他人或复用的原单。
- README、数量/大小、二进制、路径、重命名、秘密扫描、无删除/强推/自动合并等边界保留。连接测试继续使用草稿和独立目录。

## 检查与总览

helper 读取老师 main 配置，检查读取可信 PR base 配置，核对实际作者、来源、开放练习、组号格式、类型、范围和文件完整性，不执行学生代码。course-maintenance 标签由老师应用，豁免作业统计、重复检查和复用。

总览从完整 main 树和分页打开 PR 自动发现组别与提交账号，按练习/组别/类型/账号排序，分别显示个人和共同作品以及暂无提交、草稿、待审、已合并。保留仅在 main 目录出现的个人作品，不要求名单。没有全班名单时无法判断谁还没交，也不能推断共同作品代表全组个人都已交。报告只写 Actions Summary，不推 main。

课程测试只枚举根 tests/，不发现上传作品里的测试。

## 分发与验收

Skill 2.1.0，Node20+、无 npm 运行依赖，不要求学生本地 Git；完整 scripts/references、可重复 ZIP 和 SHA-256。安装器报告版本并拒绝覆盖。旧安装、目录和测试 PR 不迁移。Qoder/WorkBuddy UI、真实课堂组别及网络在合并后现场验收。

自动测试覆盖免名单的新账号、新组别、跨组/类型、实际身份及个人隔离、共享 PR 排他/并发、可信课程配置、动态总览、分页、限定测试发现、Unicode Qoder 安装及 WorkBuddy ZIP。新版 Skill 以独立消费情景验证不再错误要求老师登记。
