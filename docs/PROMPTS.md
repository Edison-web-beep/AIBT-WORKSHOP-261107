# 课程 Prompt 清单

所有提交操作使用同一个 aibt-workshop。将组号、练习和目录替换成自己的信息；IDE 已提供选中路径时，可直接说「这个文件夹」。

## 安装与连接

| 目的 | Prompt |
|---|---|
| 项目安装 | 请依 https://github.com/f3484134/AIBT-WORKSHOP-261107/blob/main/docs/INSTALL.md，在当前课程项目安装 aibt-workshop 2.1.0，保留 scripts 和 references；若已有版本先核对，不直接覆盖。 |
| 初始化和完整测试 | 使用 aibt-workshop，初始化课程并完成首次连接测试。确认实际登录账号、Fork，上传生成的文字与 PNG，创建或复用草稿 PR，读回验证并给我链接。 |
| 只诊断 | 使用 aibt-workshop，只读检查当前 GitHub 登录、课程和可用工具，列出尚未测试的写入能力。 |
| 已手动 Fork | 我已经 Fork 课程，请使用 aibt-workshop 核对 parent，再继续完整连接测试。 |
| 再次测试 | 使用 aibt-workshop，重新执行完整连接测试，先查已有测试 PR，避免重复创建。 |
| CLI 备用 | 当前 Connector 能力不足，请检查已有 Node.js 和 gh，只补齐缺少的官方工具，引导我本人完成浏览器登录，再执行完整测试。 |
| 老师测试 | 使用 aibt-workshop。我是老师 f3484134，请执行老师连接测试，保留草稿，并明确学生 Fork 尚未验证。 |

## 分组作业

| 目的 | Prompt |
|---|---|
| 提交指定目录 | 使用 aibt-workshop，提交练习一第三组的个人作品，作品在当前项目的 lesson-01-group-03 文件夹。 |
| 提交选中目录 | 使用 aibt-workshop，提交练习二第三组的个人作品，作品是当前选中的文件夹。 |
| 作品预览 | 使用 aibt-workshop，预览练习一第三组的个人作品目录，列出文件、略过项目和目的地，只读核对开放练习、实际账号及自报组别，不上传。 |
| 整理说明 | 使用 aibt-workshop，为这个作品目录整理 README，注明练习一、第三组、个人类型、作品用途、入口、做法及参考来源，先不提交。 |
| 图片/PDF/PPT | 使用 aibt-workshop，提交练习三第三组的个人作品，作品在〈目录〉；保留图片、PDF 和演示文稿原始格式，核验远端文件。 |
| 展示链接 | 使用 aibt-workshop，将公开展示链接〈URL〉补进作品 README，再提交练习四第三组的个人作品，作品在〈目录〉。 |
| 修改重交 | 使用 aibt-workshop，更新练习一第三组的个人作品，作品在〈目录〉，复用仍打开的 PR。 |
| 合并后补交 | 使用 aibt-workshop，练习一第三组的个人作品已经合并，请提交〈目录〉的新版本并创建新的版本 PR。 |
| 查询状态 | 使用 aibt-workshop，只读列出我的作品及 PR 状态、链接和是否等待老师合并。 |
| 观摩同学 | 使用 aibt-workshop，只读查看练习一各组公开作品与 PR，不修改或评论。 |

## 代表提交小组作品

```text
使用 aibt-workshop，代表第三组提交练习一的小组共同作品，作品在当前选中的文件夹。
```

同一人可以代表多个组，无需预建名单；每次明确一个练习和组号。也可同时交自己的个人作品，两类使用独立目录和 PR。仅说「提交练习一第三组」而未说明类型时，Agent 会补问个人还是小组。

## 故障与重试

| 情况 | Prompt |
|---|---|
| 网络中断 | 刚才提交练习一第三组个人作品时断线，请先查远端文件和 PR，再继续提交〈目录〉，避免重复创建。 |
| 换了 IDE | 使用 aibt-workshop，重新确认当前 Qoder/WorkBuddy 的账号及连接，不假设另一个工具的授权可以共用。 |
| 登录错账号 | 先停止上传，确认实际登录账号，引导我本人切换为自己的学生账号后重新核对。 |
| 第一次交新组别 | 使用 aibt-workshop，提交练习一第八组的个人作品，目录是〈目录〉；组别由我填写，无需预先登记。 |
| 填错组号 | 我刚才填错组号，请先列出错组 PR 和文件位置，协助我联系老师处理，再按正确组号重交；不要自动移动或删除旧作品。 |
| 同名仓库冲突 | 检查同名仓库是否为本课程 Fork，不删除或覆盖不相关仓库。 |
| 原因不明 | 列出账号、课程配置、组号、Fork、上传、PR 哪些通过，给一个明确下一步，不虚报成功。 |
